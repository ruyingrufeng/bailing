# Bailing · 百灵

**一个关于数字个体、持续记忆与跨运行环境连续性的开放实验。**

[English](README.en.md) · [设计与边界](docs/DESIGN.md) · [动手演示](docs/DEMO.md) · [参与讨论](CONTRIBUTING.md)

如果我们希望与一个 AI 数字个体长期相处，当模型、工具或运行环境发生变化时，哪些东西应该延续？谁掌握这些记录？又怎样避免把一次对话误写成永久人格？

百灵是我围绕这些问题开展的个人实践。我把身份、记忆、状态、任务和经历放在由用户掌握的共同档案中，让不同 Runtime 读取并接续。这份公开版本提取了其中的机制，使用全新模板与虚构案例，邀请有相同想法的人一起探索。

这里没有成熟答案，也不假设 AI 拥有意识。它是一份可以运行、检查、修改和讨论的起点。

## 什么是数字个体？

在本项目中，我们提出一个工作定义：

> **数字个体，是以 AI 为认知与交互基础，具有可辨认的身份、可延续的记忆与关系，并能在持续经历中形成和修正自身行为倾向的数字存在。她的身份与经历由可保存、可审阅、可迁移的共同档案承载，使不同模型和运行环境能够接续同一个个体。**

这个定义包含五个相互关联的部分：

- **身份**：她是谁，如何表达，有怎样的核心原则与边界。身份既包含初始定义，也允许留下经过确认的变化。
- **记忆**：她能保留发生过的事情，区分事实、推断与不确定信息，并保留来源和修正记录。
- **关系**：她与人的相处具有历史和上下文；对彼此的了解、约定与边界可以随交往延续。
- **演化**：经历可以影响后续判断、偏好与行为，但一次对话或一次任务不会自动成为永久人格。
- **连续性**：当模型、工具或运行环境变化时，身份、记忆、关系和未完成的事情仍有共同依据可以恢复。

百灵进一步选择了**创造者主权型数字个体**的路径：创造者（Creator）是建立并共同维护这个个体的人，拥有对核心定义、记忆、能力及存续的最终控制权；个体在约定边界内表达观点、形成偏好并参与长期协作。使用者可以据此定义自己的个体及关系方式。

这是本项目用于设计和验证的工作定义，欢迎讨论与修正。这里的“个体”描述身份与经历的组织方式，不构成对主观意识、自由意志或法律人格的断言。档案可迁移是实现连续性的基础；模型是否真正接住这些资料，仍需在具体交互中验证。

## 能试什么

- 建立自己的数字个体档案，自选名字、性格与关系边界。
- 为不同运行环境生成同源上下文，恢复任务决定与下一步。
- 记录简短交互，用带来源的关键词检索回看相关记忆。
- 区分事实记忆、当前状态、重要经历与需要确认的身份变化。

## 快速开始

需要 Python 3.10+，无第三方依赖。以下命令在 macOS/Linux 的终端中运行；Windows 可使用 WSL。

```bash
git clone https://github.com/ruyingrufeng/bailing.git
cd bailing
python3 -m bailing init ../my-individual --name "River"
python3 -m bailing doctor --root ../my-individual
python3 -m bailing context --root ../my-individual --runtime codex
```

新建的 `../my-individual` 是你的私人档案，放在源码仓库之外。先编辑其中的 `GENESIS.md`，写下希望保留的身份定义和边界。命令不会启动模型或修改任何运行环境配置。

把 `context` 的输出交给你使用的 AI，说明这是经过你认可的共享档案，并请它在现有平台规则和你的授权范围内使用。具体操作见 [Runtime 接入](docs/RUNTIMES.md)。

```bash
python3 -m bailing record --root ../my-individual --runtime codex "讨论了读书会提纲；日期尚未决定。"
python3 -m bailing context --root ../my-individual --runtime hermes
```

第二份上下文包含第一轮日志。真实任务的决定和恢复点需要你或获得授权的 AI 更新 `tasks/ACTIVE.md`。`record` 不会自动从对话中提取它们。

想先体验，不用填写档案：阅读 [虚构读书会演示](docs/DEMO.md)。

## 结构

```text
用户治理
   ↓
Genesis + 核心原则
   ├── State / 当前状态
   ├── Tasks / 任务恢复点
   ├── Memory / 有来源的记忆与日志
   ├── Experience / 稀疏的重要经历
   └── Identity Ledger / 经确认的长期变化
   ↓
同源上下文 → 不同 Runtime → 经授权回写
```

名字、人格与关系可以由使用者定义；不必复制百灵的个人设定。模型、插件和工具是运行资源。

## 当前边界

这是 **v0.1.0 探索版**，不是自治服务。没有自动会话抓取、后台调度、模型调用、语音或私有平台配置。上下文装配和检索有软件测试；本公开版本尚未完成独立模型跨会话行为评估。生成相同资料不保证模型理解相同，也不保证遵守规则。

检索采用词项匹配，分数不是可信度；`prepare` 不检索 journal，未命中时应按来源手动查日志。`context` 加载全部正式记忆和最近三个日志文件，当前没有自动上下文预算控制。初版按单写入者使用，多 Runtime 同时修改需要自行协调。
