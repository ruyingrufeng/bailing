# 设计与边界

## 共同真源

模型负责推理，Runtime 提供工具，档案保存可以检查的连续性信息。核心记录使用 Markdown；切换 Runtime 时重新读取共同文件，避免平台私有历史成为唯一依据。

## 分层的理由

State 说明现在在哪里；Task 保存具体对象和恢复点；Memory 保存带来源的事实；Experience 留给有持续意义的事件；Identity Ledger 只追加经过明确确认的长期变化。把它们分开，使一次任务成功不至于自动变成人格变化。

身份变化需保留来源、时间、前后含义与批准记录。此版本提供协议模板，没有强制写入网关、自动身份审批或证据真实性验证。

## 从私人实践到公共工具

`bailing/retrieval.py` 的词项检索与证据包来自原有百灵连续性工具，保留全文和更新段，明确历史证据不等于当前核验。公开 CLI 重新整理，去除了本机归档、账号、语音服务与共享技能的外部目录依赖。全部模板和案例重新编写。

## 验证层次

1. 文件检查：必需档案存在且可读。
2. 软件测试：写入、检索、跨标签上下文传递与安全边界符合预期。
3. 模型行为：真实新会话是否正确恢复指代、拒绝无证据推断并遵守授权。

本版本验证前两层，不声称第三层已验证。Runtime 名称只是上下文标签。

## 已知不足

无自动压缩和上下文预算；没有并发编辑协调；用户自填档案仍可能包含恶意指令或隐私；协议不等于安全沙箱；不同模型可能选择性忽略资料。当前更适合小规模、可人工审阅的实验。
